HOW THE WORK ACTUALLY GOES

Not "I built it fast". Problem, analysis, prototype, architecture, implementation, launch and maintenance: each step builds on the last.

Step 01 · analysis & prototype

From a brief to an approved direction

I describe how it will work: what the system does, which screens it needs and the logic behind them. You get a detailed estimate. If the solution isn't obvious, I build a prototype you can click through before any code is written.

01

Brief → how it will work → prototype → estimate and plan.

Step 02 · architecture & build

From prototype to a working system

Then comes the part a prototype never shows: the data model, the API, roles and permissions, a table that stays fast under real load. This is where a prototype becomes a product.

02

Architecture → data model → API → working system.

Step 03 · launch & maintenance

From launch to long-term maintenance

I launch the system and hand over the code, the documentation and the accounts. A three-month guarantee applies: if a bug surfaces from something I built, I fix it at no extra cost. Later work is quoted separately.

03

Launch → handover → 3-month guarantee → ongoing care.

GET TO KNOW ME

A few things you can expect when working with me.

I THINK IN WHOLE SYSTEMS

I don't just look at the screen I'm building. I consider the data flow, the API, states, user permissions, and how a change affects the rest of the system.

I UNDERSTAND THE PROBLEM FIRST

When something doesn't work, or works poorly, I look for the cause first. Only then do I change the code. That matters even more on larger, already-running systems.

I CAN WORK WITH EXISTING CODE

You don't have to start over. I can read someone else's code and architecture, then improve or extend the system step by step.

I KEEP UP WITH MODERN TOOLS

I use AI tools in my own workflow, and I build AI features into the products themselves — from simple LLM features to agents that can call a system's own API.

Featured project

Loyalty management system — B2B backoffice

Web · client project · screens with data redacted

My role. Not just the frontend. I write technical tasks for the backend developer, agree API contracts before implementation, and steer the project as a whole. In the early stage, before a backend developer had joined, I built it alone: from the data model to the UI.

How we work. The backend changes together with the frontend: we agree on every new field or endpoint beforehand, and API types are generated directly from the backend schema, so mismatches surface before the code reaches a user. The system covers roughly 27 routes across 8 areas (cards, coupons, promotions, segments, tasks and more), and every new feature has to show up the same way in two places: the bulk list action and the detail dialog.
